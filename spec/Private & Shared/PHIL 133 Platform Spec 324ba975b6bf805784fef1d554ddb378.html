1.4 JSON File Model

Projects will possess the following characteristics:

  • Circuit data
  • Metadata
    • title, author, date

Circuit structures are serialized into JSON formats so enable exporting and sharing of files. They include all relevant:

  • component data
  • position data
  • connection data
  • parameters

JSON format is suggestive, if needed, data can be added/reorganized to whatever is most convenient

1.5 Save/Load Data

  • Project serialized into JSON
  • File locally saved
  • Success message

Load Flow:

  • Select open
  • JSON file uploaded
  • Circuit data is verified
  • Circuit is reconstructed in workspace
  • UI refreshes

2. Foundation

2.1 Workspace

Editor contains two-dimensional workspace to build circuits, Finite State Machines, Turbots, Turing Machines. System provides visual editor for allowing students to drag-and-drop interaction.

Users select elements from the component palette and place them in the workspace canvas. Each component becomes an independent instance that can be moved, connect, and deleted.

Features

  • Infinite or large scrollable canvas
  • Zoom in/out functionality
  • Pan navigation via mouse drag or trackpad
  • Background grid visual
  • Snap-to alignment for components

2.2 Selection Editing

Users can utilize traditional editing tools to manipulate component and links

Editing Functionality

  • Single select
  • Multi select
  • Box select
  • Movement
  • Copy/Paste
  • Delete
  • Undo/Redo
    • Component creation
    • Movement
    • Wiring
    • Deletion
    • Parameter Changes

3. Component Library

3.1 Inputs and Outputs

  • Inputs and Outputs
    • User controlled
    • Boolean values
    • Combinatorial Circuits (CCs)
      • Input/output table
    • Sequential Circuits (SCs) and Finite State Machines (FSMs)
      • Input/output table with time increments
    • Turing Machines
      • Input/output tapes

Input can be inserted into circuit either through the designated text boxes directly in the workspace, or inputted into the input/output or argument/value table.

  • Typing an input into either of these fields will automatically populate the other

Input boxes are automatically labelled depending on their vertical component (higher up, the lower the value).

  • the labelling of an input box does NOT change after being created
    • if any lower input box is moved to be higher than other, this does not alter either labels

Outputs are labelled and dealt with identically to inputs

3.2 Initial Components

  • Basic Logic Gates
    • NOT
    • AND
    • OR

Each logic gate contains:

  • Defined input ports
  • One output port
  • Logical evaluation functionality

3.3 Additional Components

  • MEMORY
  • State blocks
  • Turbot
  • Turing Machine

4. Drag and Drop Functionality

4.1 Component Creation

When component is dragged from library onto canvas a new component instance is created with the following properties:

  • Component type
  • Workspace position
  • Input/Output ports
  • Unique identifier

A component can also be placed by selecting it in the library, and then selecting where it should be placed in the workspace.

4.2 Movement

Moving a component around preserves:

  • Type
  • Identifier
  • Preexisting wiring

4.3 Ports

Each component will have visible connection ports, representing the valid connection points for single flows. Input ports receive signal, while output signals send signals

5. Circuit Functionality

5.1 Wiring System

Users can create links between components to build circuits. Links adhere to the following rules:

  • Connections are only allowed from an output port to an Input port
  • One Output port may connect to multiple Input ports
  • Invalid connections are not allowed visually
  • Can only consist of straight lines
    • Horizontal and vertical lines follow grid lines
    • Diagonal lines begin and end at grid vertices
  • When wires cross, a “bump” is created to indicate correct pathways
  • Values propagate through wires by colour
    • Black indicates “0”
    • Red indicates “1”

Mockup of Wire Functionality

5.2 Basic Logic Gate Evaluation

Each logic gate must evaluate outputs depending on their respective truth table

Whenever and input is changed:

  • connected gates recompute outputs
  • signals propgate through links
  • output values update visually

6. Combinatorial Circuits

Outputs are evaluated directly from the inputs, without any internal memory.

Simulator evaluates combinational circuits by recomputing gate outputs whenever inputs are changed.

7. Sequential Circuits

Introduce the additional component MEM block

7.1 Time Model

  • Maintains a discrete time step
  • Each time step represents a clock cycle

7.2 Visualization

  • Inputs and outputs tracked using input/output table with time step
  • Time step tracker display

8. Finite State Machines

States are represented as computational blocks, with arrows notating state changes

Each FSM will contain:

  • Set of states represented by state blocks
    • Can be labeled
  • Transition Rules
  • Inputs/outputs

Simulation displays:

  • current state
  • execution of the FSM

10. Turbots

10.1 Arena

The working space for turbots will allow for the placement of the following additional components:

  • Turbot
    • can be oriented in any four of the cardinal directions
  • Blocks
    • Used to restrict movement
    • Functionally a way to restrict from an infinite arena to a finite arena
  • Food

10.2 Internal Circuitry

Turbots can contain any of the above types of circuitry.

  • Linked workspace between the turbot and its internal circuitry that dictates its behaviour

11. Evaluation

11.1 Back-end Instructor Evaluation

Platform should support automatic grading of circuits through submission of files. Evaluation portion of platform should be inaccessible to students.

11.2 CCs and PCs Evaluation

  • Compares generated outputs with expected outputs
    • depending on truth tables
  • Sequential circuits require checking outputs across all time steps

11.3 FSMs, Turbots, and Turing Machine Evaluation

  • Compares expected states and outputs across time steps
